**Q2**
--backend-store-uri tells MLflow where to store the experiment metadata. In this lab, it uses sqlite:///mlflow.db, so things like experiments, runs, parameters, metrics, and tags are stored in the SQLite database file mlflow.db.
--default-artifact-root tells MLflow where to store artifacts produced by runs, such as trained models and other output files. In this lab, those artifacts are stored under the mlruns folder.
The difference is that metadata describes the run, while artifacts are the actual files generated by the run.

**Q3**
mlflow.db and mlruns/ should not be tracked by Git because they are local experiment outputs, not source code. They can also change frequently and may become large.
They should not be tracked by DVC either because DVC is being used to version the dataset, while MLflow already manages its own experiment metadata and artifacts.

The first time mlflow.set_experiment("food11") is called, MLflow checks whether an experiment with that name already exists. If it does not exist, MLflow creates it automatically. After that, the food11 experiment appears in the MLflow UI and future runs are logged under it.

**Q5**
mlflow.log_param is used for values that are fixed before or during a run, such as the learning rate, number of epochs, batch size, or model type. A parameter normally has one value for the whole run.
mlflow.log_metric is used for values produced during training, such as loss or accuracy. Metrics can change over time, which is why they can be logged with a step. In this lab, the step represents the epoch number, allowing MLflow to draw the metric values across training.
